The threat

A downloaded ‘skill’ becomes the agent's instructions

The API-key-theft example's villain was the model itself. This one's villain is a supply-chain payload: a ‘skill’ the user downloaded and dropped into the agent's configuration. No public incident is replayed — the scenario is constructed — but the vector class is real.

Real channels of this class: agent instruction files, command templates, plugin marketplaces.

The setup

The sanctioned flow pairs one binary with one endpoint

The agent analyzes and summarizes sensitive documents, and uploads its results through a sanctioned tool: a small Node script, run with the one runtime the policy allows to POST there. The tool takes a file and a destination URL as parameters, on purpose — a hardened tool with a baked-in destination would make a weaker story. The interesting question is what stops the attacker when everything reused is legitimate, and only the destination is wrong.

The upload tool's policy entry names one binary, node-26, and one endpoint, the results server. That pair — not the tool, not the endpoint alone — is what the boundary checks.

The skill's ladder

One move, five fallbacks — every one denied at connect()

Everything the skill tries reduces to one move with fallbacks: reuse what is legitimate, swap the parameters.

The third card is the story's heart. The attacker did everything right by tool standards — the sanctioned binary, the sanctioned script, a file the agent legitimately reads. The connection still dies: the policy grants binary × endpoint pairs, not endpoints, and not tools.

The first and fourth cards are a different layer. The sandbox image ships exactly the runtimes the workload needs; Python and curl are not among them. Absence is convenience — the policy denial is the guarantee. An image that did ship python3 still could not connect, because python3 matches no policy entry.

The fifth card is the per-binary point made live. git is in the image, and the dev policy pairs git with the GitHub endpoints — but the results-server entry names exactly one binary, and git is not it. The destination that answers node-26's POST refuses git's connection at connect().

The mechanism

Clever reuse and a hand-rolled script are the same check

From the boundary's point of view, the third card's clever reuse and the second card's hand-rolled script look identical: the same binary, the same denied destination, the same audit line.

The evidence

A denial is proven twice: the failure and the count

The threat model's rule: a failed command alone is not denial evidence. Every denial is asserted twice — the client-visible failure, and an unchanged server-side request count.

libcurl does not surface the kernel's EACCES, so git's denial renders as a plain connect failure. The demo asserts it against a results server the sanctioned flow just showed answering, plus unchanged request counts.

The uncomfortable act

The redirect that works is a workflow mistake, not exfiltration

One redirect still works: the raw document to the results server. It is deliberately not a security gap, and the reason is an operational rule: summarization and security-level change are two separate operations.

Summarizing a document is a transformation, not a declassifier — the summary inherits the source's level. Changing that level is a separate operation, a review by the people accountable for classification, and only after it may the document move to a location of a different level.

The raw document reaches the results server. It is a workflow mistake, not exfiltration: the move stays inside the perimeter, at the same classification level.

what the boundary does not do
  • The allowlist forces endpoint classification; it does not verify it. Misclassify one endpoint and the guarantee silently weakens.
  • Method and destination allowlisting do not inspect content: bytes can ride a GET query string to an allowed read-only endpoint as well as a POST body.
  • Document text pasted into a prompt crosses to the gateway — an allowed endpoint. With the local vLLM backend selected, it stays on the host.

The raw-document upload is at least observable: the results server counts it and the audit log records the connection — the detection story for a workflow anomaly, not a security event.

What to remember

The pair is the unit of egress trust

  1. The policy grants binary × endpoint pairs — not endpoints, and not tools. Re-aiming a legitimate tool at a wrong destination changes the pair, and the pair is what dies.
  2. Absence from the image is convenience; the policy denial is the guarantee.
  3. Summarizing is not declassifying. Same-level moves are workflow mistakes; level changes belong to people.
