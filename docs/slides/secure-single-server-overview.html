Coding agents get a perimeter on one RHEL host

OpenCode and OpenClaw run inside an OpenShell sandbox, reach models through a Praxis gateway, and ship as a bootc image.

Experimental RHEL 9 OpenShell Praxis bootc
Pavel Anni · Office of the CTO · Red Hat
The problem

A coding agent reads your files, runs commands, and calls a model

Those abilities make a harness useful. They also raise four questions the harness does not answer by itself.

  • Files and commands. Which paths can the agent read and write, and which binaries can it run?
  • Model traffic. Where do prompts and responses go?
  • Credentials. Who holds the provider keys?
  • The host. How does the machine stay consistent from one deployment to the next?
The gap

In an ordinary container the app holds the real key

Ordinary container

Everything sits inside the app

  • The real model key lives in the app process
  • The app can write to its own directory
  • The app can read a marker outside its directory
OpenShell sandbox

The perimeter sits around the app

  • The app gets an opaque placeholder, and OpenShell swaps in the real key for one authorized endpoint
  • The app directory is read-only
  • The marker outside the allowed paths is unreadable
Source: docs/examples/streamlit-security

How it works

Each concern has exactly one owner

OpenShell

Workspace and tools

Declared writable paths, read-only paths, approved binaries, and network destinations.

Praxis

Model routing

One gateway endpoint for the harness, with a local or external upstream behind it.

Praxis or provider profile

Provider credentials

Keys stay out of ordinary harness configuration.

bootc

Host consistency

The reviewed host environment and pinned workload references ship as one OS image.

The proof

Three attack scenarios stop at the same perimeter

API key theft

Planted key

The key is discoverable. Attempts to spend it outside the approved gateway are blocked and audited.

Document exfiltration

Malicious skill

The skill tries several ways to send a document to an attacker destination. The boundary blocks each one.

Model escalation

Unapproved model

The gateway catalog refuses the model before any credential is used.

Source: docs/examples
Deployment

One bootc image repeats the host

  • Image variants exist for OpenCode and OpenClaw.
  • First boot pulls the selected control-plane and harness images into rootless Podman storage.
  • Manual Podman install supports the same post-deployment scenarios.
  • Workspace data needs its own storage plan, because the host image does not preserve it.
What you can do

Agents keep working after your laptop disconnects

  • Queue public GitHub issues or prompt files for a public repository.
  • Keep a longer batch alive in tmux after you drop the SSH session.
  • Collect one bundle per task: the task, a proposed patch, metadata, and a report.
  • Apply the bundle on your workstation and open a draft PR with your own Git and GitHub credentials.

The sandbox receives no GitHub token and has no GitHub write access.

Source: docs/examples/opencode-pr-queue
Limits

Treat it as an experiment on a disposable host

  • Not production-ready. Review the qualification evidence before you extend a deployment.
  • One trusted administrator. OpenShell here is not a multi-tenant authorization system.
  • Qualified combinations only. The compatibility matrix lists what was exercised.
  • Profile-dependent limits. Praxis routing and quotas follow the selected profile and upstream.
